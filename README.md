# Ля Вуа Лакте — лендинг

Сайт молочного завода ООО «Ля Вуа Лакте» (бренд «Токтогул сүт»).

Одна страница: полноэкранная 3D-история «Путь молока» — молоко льётся, свёртывается в творог,
прессуется в головку сыра, созревает в погребе и превращается в продукцию. В финале — плоская 2D-сцена:
молоко плещется и растекается по экрану. История идёт по прокрутке. Ниже — блоки «О заводе», «Продукция», «Контакты».

Сайт раздаётся маленьким Node-сервером без зависимостей. Деплой — Railway (автоматически при пуше в `main`).

## Запуск локально

```
npm start
```

Откроется на http://localhost:3000 (порт берётся из `PORT`).

## Как устроено

3D нарисовано на чистом WebGL2, без библиотек и без картинок: каждая сцена — это шейдер,
поэтому всё процедурное. Сцена 0 («текучее молоко») — карта высот с вихрем, сцены 1–3 — raymarching
по полям расстояний, сцена 4 — 2D-жидкость (см. ниже).

- `public/index.html` — разметка, тексты глав, секции под историей
- `public/site.css` — стили (имя менялось намеренно: старый styles.css застрял в кэше браузеров)
- `public/js/shaders.js` — GLSL: 5 сцен (текучее молоко, творог/пресс/сыр, погреб, продукция, 2D-молоко), шейдеры симуляции жидкости (`SIM`), `RESOLVE` (накопление кадров),
  `POST` (бикубическое увеличение, резкость, блум, тональная компрессия, молочная «шторка» между сценами) и `FXAA`
- `public/js/stage.js` — WebGL: сцена → накопление → пост-проход, адаптивное разрешение
- `public/js/i18n.js` — тексты на 4 языках (кыргызский — основной, русский, французский, английский)
- `public/js/main.js` — прокрутка → прогресс истории, тексты глав, меню, ссылки WhatsApp
- `server.js` — статический сервер: brotli/gzip из памяти, ETag и 304

Если WebGL2 недоступен, страница показывает обычную версию без 3D (`html.no-gl`).
Анимация сама снижает разрешение, если видеокарта не тянет; при `prefers-reduced-motion` время замирает.

### Графика: чёткость и плавность

Конвейер кадра: сцена рисуется в HDR-буфер (RGBA16F) с субпиксельным дрожанием камеры (Halton 2,3) →
`RESOLVE` накапливает кадры (TAA: история ограничивается по соседним пикселям, поэтому нет «шлейфа»;
при прокрутке или движении мыши вес нового кадра растёт) → `POST` увеличивает результат до размера холста
бикубикой Catmull-Rom, слегка поднимает резкость (ограничено соседями — без ореолов), добавляет блум
(4 выборки на уровень, без блочности), тон и виньетку → `FXAA` на размере экрана (убирает «ступеньки», пока накопление
не успевает: при прокрутке) и дизеринг. В накоплении история отбрасывается там, где не сходится с соседями (движение у краёв).
В raymarching после цикла делается досадка до поверхности (2 шага) — края предметов ровные, без «зубцов»;
в сцене 1 тяжёлая карта считается только внутри ограничивающего шара.

- Холст — CSS-размер × min(devicePixelRatio, 1.5), не больше ~2 Мп; на телефонах DPR до 2 и до ~1,9 Мп; размер меняется с задержкой 140 мс.
- Разрешение сцены — по ступеням (на телефонах 0,36 … 0,9 от холста), отдельно для каждой сцены. Кадр сравнивается с частотой экрана
  (она определяется по минимальному интервалу между кадрами: 60 Гц → кадр 16,7 мс уже «быстрый»), иначе на экранах 60 Гц разрешение
  никогда бы не росло. Падает при кадрах >~28 мс, растёт только когда все шейдеры уже собраны. Единичные подвисания драйвера не учитываются.
- Бесшовность: каждый шейдер после сборки один раз прогоняется по буферу 8×8 (драйвер заканчивает компиляцию заранее).
  Если следующая сцена ещё не готова, прокрутка упирается в молочную шторку и плавно её удерживает, а не показывает чужую сцену.
- Сервер сжимает текст (br/gzip) и отдаёт ETag; HTML/CSS/JS кэшируются с обязательной проверкой, шрифты Google подгружаются без блокировки.

### Производительность шейдеров

Сцены компилируются по одной в фоне, пока пользователь читает первый экран. На Windows (ANGLE/D3D11)
компилятор FXC очень болезненно относится к шумам и многократно вызываемой `map()`: раньше сцена 1
собиралась ~15 с и драйвер сбрасывал WebGL-контекст (страница падала в версию без 3D). Поэтому:
в `map()` — только дешёвый синусный шум (`fbm` — только в шейдинге и 2-октавный `fbmL`),
отражения в полу идут по упрощённой карте `mapR`, освещение вызывается из одного места.
В сцене 1 готовая головка сыра не считает каплю и творог (ветки по uniform'у) — в 3,5 раза быстрее; положения комочков творога — константы.
На телефонах (`COARSE`) марш и тени короче. Вырез «глазков» в сыре сцены 3 не должен обнулять расстояние под коркой (ломались нормали, на мобильных GPU — полосы).
Хеши в пост-проходах без `sin()` (на мобильных GPU он даёт узоры). Замер: сцены собираются за 0,06 / 2,7 / 1,3 / 2,2 с. При добавлении в шейдер новых `fbm`/`map()` проверяйте время.
Если контекст всё же теряется, страница один раз перезагружается, а затем показывает обычную версию.

### Сцена 5: 2D-молоко

Настоящая симуляция жидкости на GPU («stable fluids»), а не анимация-картинка. Поле скорости (короткая сторона 120 px, на телефонах 88)
и толщина молока (540 / 360 px) — текстуры RGBA16F. За кадр: всплески (аддитивный блендинг) → вихри → завихрённость и тяжесть →
дивергенция → давление (Jacobi, 22 / 14 итераций) → вычитание градиента → перенос скорости и молока. Толщина слегка
«подтягивается» к плато (молоко держит форму лужи), а у нижнего края стекает. Шейдер `MILK2D` рисует молоко по изолинии толщины:
мениск (нормали по градиенту), блик, фреснель, тень на тёмном фоне; низ и верх экрана затемнены, чтобы читались текст и меню.
Если нет float-рендеринга (`!floatRT`), сцена пропускается.
- Всплески: сценарий по прокрутке (`EVENTS` в `stage.js`, воспроизводится заново при прокрутке назад), спокойные случайные каждые ~2–3 с,
  мышь/касание размешивают молоко, клик/тап — новый всплеск, быстрая прокрутка тоже размешивает.
- История стала длиннее: `.story` 1300vh (было 900vh). Прогресс глав в `index.html` и `CUTS` в `stage.js` пересчитаны; сцена 5 идёт с P≈0.71 до 1.
- Замер (интегрированная графика, без ограничения 60 Гц): ~6,8 мс/кадр на 1265×720 и в эмуляции S22 Ultra. Параметры «заливки»:
  растворение молока `uDiss` (0,14), сток у низа экрана, размеры случайных всплесков.

### Языки

Переключатель KY / RU / FR / EN в шапке. По умолчанию открывается кыргызский; выбор запоминается в браузере,
`?lang=fr` принудительно задаёт язык. В `index.html` у элементов стоят `data-i18n="ключ"`, сами тексты — в
`public/js/i18n.js`. Чтобы поправить перевод, достаточно отредактировать словарь (и, для кыргызского, такой же
текст в `index.html` — он показывается до загрузки скриптов). Латинское написание бренда («La Voie Lactée»,
«Toktogul süt») пока предположительное — уточнить у владельца.

### Отладка

Параметры в URL: `?p=0.3` — зафиксировать прогресс истории (0…1), `?t=2.5` — зафиксировать время,
`?scale=0.5` — фиксированный масштаб рендера, `?debug` — показать лог ошибок шейдеров.
В консоли: `LVL.go(0.3)`, `LVL.stats()`.
